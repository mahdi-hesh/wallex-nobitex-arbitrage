# پایشگر آربیتراژ والکس و نوبیتکس (نسخه آزمایشی)

این برنامه فقط داده عمومی بازار را می‌خواند و **هیچ سفارش یا معامله‌ای ثبت نمی‌کند**.

## قابلیت‌ها
- دریافت فهرست بازارهای والکس و دفتر سفارش همه بازارها از API عمومی رسمی.
- دریافت دفتر سفارش همه بازارهای نوبیتکس و زمان آخرین به‌روزرسانی.
- تطبیق دارایی پایه و مظنه؛ تبدیل مظنه ریالی/تومانی به ریال (هر تومان = ۱۰ ریال).
- محاسبه اختلاف از روی Ask خرید و Bid فروش و پیمایش عمق سفارش.
- شرط سخت‌گیرانه اختلاف ناخالص `> 2%`.
- محاسبه تقریبی سود خالص با کارمزدهای Taker تنظیم‌شده.
- هشدار تلگرام فقط برای فرصت تازه یا تغییر معنادار.
- ذخیره وضعیت هشدارها در `state.json`.

## محدودیت مهم نسخه اول
1. کارمزدهای واقعی حساب به سطح کاربری و نوع بازار بستگی دارند. تا زمانی که مقادیر صحیح `WALLEX_TAKER_FEE` و `NOBITEX_TAKER_FEE` را از حساب خود وارد نکنید، سود خالص تأیید نمی‌شود.
2. وضعیت فعال بودن واریز/برداشت و شبکه انتقال به حساب و زمان وابسته است و از دفتر سفارش عمومی قابل اثبات نیست. بنابراین نسخه اول همه فرصت‌ها را «تأییدنشده/غیرقابل اجرا» علامت می‌زند؛ حتی اگر سود خالص تخمینی مثبت باشد.
3. کارمزد انتقال در محاسبه خالص لحاظ نشده است؛ به همین دلیل `TRANSFER_ROUTE_CONFIRMED` عمداً روی `false` قرار دارد. تغییر آن به `true` فقط پس از بررسی دستی موجودی دو صرافی، وضعیت واریز/برداشت، شبکه یکسان و هزینه انتقال مجاز است.
4. برای آربیتراژ واقعی معمولاً باید از قبل موجودی ریالی/تتری و رمزارزی را در هر دو صرافی تأمین کرده باشید؛ انتقال پس از مشاهده فرصت ممکن است فرصت را از بین ببرد.
5. داده‌های دو API دقیقاً در یک لحظه گرفته نمی‌شوند. برنامه فاصله دریافت را محدود می‌کند و داده قدیمی نوبیتکس را کنار می‌گذارد؛ اما این تضمین هم‌زمانی کامل نیست.
6. API والکس در پاسخ دفتر سفارش همه بازارها timestamp مستقل برای هر بازار نشان نمی‌دهد؛ زمان دریافت محلی ثبت می‌شود.
7. در نسخه فعلی، بازارهایی که quote آنها به صورت تومان/ریال یا یک استیبل‌کوین مشترک قابل نرمال‌سازی است مقایسه می‌شوند. تبدیل نرخ بین USDT و ریال انجام نمی‌شود.

## راه‌اندازی در GitHub
1. یک Repository جدید بسازید. برای استفاده رایگان از GitHub-hosted Actions می‌توانید مخزن را Public انتخاب کنید؛ کد این پروژه هیچ رمز یا توکن واقعی ندارد. اگر Private می‌خواهید، سهمیه دقیقه‌های Actions حساب را بررسی کنید.
2. فایل‌های این بسته را در ریشه مخزن بارگذاری کنید؛ پوشه `.github/workflows` باید حفظ شود.
3. در مخزن بروید به `Settings > Secrets and variables > Actions > New repository secret` و این موارد را اضافه کنید:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
   - `WALLEX_TAKER_FEE`
   - `NOBITEX_TAKER_FEE`
4. کارمزد Taker را از حساب/پشتیبانی هر صرافی دقیقاً به درصد وارد کنید؛ مثال `0.25` یعنی ۰٫۲۵ درصد. اگر نرخ را نمی‌دانید خالی بگذارید؛ برنامه فرصت را تأییدشده نمی‌نامد.
5. در تب `Actions`، در صورت درخواست GitHub گزینه Enable workflows را بزنید و سپس `Crypto arbitrage monitor` را با `Run workflow` یک‌بار دستی اجرا کنید.
6. اجرای زمان‌بندی‌شده هر ۱۰ دقیقه است. GitHub زمان اجرای cron را تضمین نمی‌کند و ممکن است با تأخیر اجرا شود.

## گرفتن Chat ID
1. در تلگرام ربات خود را باز کنید و `/start` بفرستید.
2. برای دریافت Chat ID می‌توانید روی رایانه Python و requests نصب کنید و فایل `get_chat_id.py` را با متغیر محیطی `TELEGRAM_BOT_TOKEN` اجرا کنید؛ یا از مرورگر، آدرس زیر را با توکن خود باز کنید:
   `https://api.telegram.org/bot<TOKEN>/getUpdates`
3. مقدار `message.chat.id` را بردارید. توکن را در پیام یا مخزن عمومی منتشر نکنید.

## هشدار
این ابزار تحلیل و اعلان است، نه توصیه سرمایه‌گذاری و نه تضمین سود. عمق سفارش، کارمزد، محدودیت برداشت، شبکه انتقال و قیمت ممکن است پیش از اجرا تغییر کنند. پیش از هر اقدام، هر دو سمت معامله و موجودی را در رابط رسمی صرافی بررسی کنید.


### پیوند بازار در اعلان
در پیام تلگرام، برای هر سمت معامله پیوند مستقیم API دفتر سفارش همان نماد قرار می‌گیرد. این پیوند داده بازار است، نه صفحه ثبت سفارش؛ مسیر صفحه معاملاتی وب ممکن است با تغییر رابط صرافی عوض شود.
